## 1. 实现摘要（5 个单元）

| 单元 | 函数 | 做了什么 |
|---|---|---|
| 1. MinerU SDK 对接 | `_sync_mineru_call` / `_call_mineru` | 同步 `MineruKIEClient` 上传 + 轮询，用 `tempfile` 落临时 PDF（finally 清理），外层 `asyncio.to_thread` 包裹不阻塞事件循环；兼容 parse 为 dict 或带 `get_result()` 的结果对象 |
| 2. 容错归一化 | `_norm_type` / `_pick` / `_extract_page` / `_find_block_list` / `_mineru_to_blocks` | 递归定位 block 列表，按别名优先级提取 content/page/bbox/image，type 归一为 text/table/figure/formula；未知结构 warning 不抛错 |
| 3. 图片落 MinIO | `_minio_client` / `_decode_image` / `_sync_put_object` / `_sync_presigned` / `_upload_figures` | 先写库拿 `block_id` → 拼 key `{user_id}/{paper_id}/{block_id}.png` 上传 figures bucket → `UPDATE doc_blocks` 回填 `image_key`；单图失败 warning 不中断 |
| 4. VLM 图描述 | `_describe_figures` | 复用并发逻辑，改用 MinIO presigned URL 供 VLM 访问；失败 warning |
| 5. 参考文献 + 落库 | `_extract_refs_llm`（沿用）/ `_write_blocks` / `_write_citations` / `parse_paper` | `_write_blocks` 用 `lastrowid` 回填 `block_id`；`parse_paper` 串联新顺序并末尾 `UPDATE papers.status='done'` |

## 4. 容错归一化字段映射假设表（⚠️ 真实联调需核对修正）

SDK 文档未给出 `results['parse']` 内 block 的确切结构，以下为**我方假设的兼容映射**。真实接通 MinerU 后，请对照实际返回 JSON 核对，不符处调整 `_mineru_to_blocks` 与各助手的候选键：

| 目标字段 | 候选键（按优先级） | 备注 |
|---|---|---|
| block 列表位置 | `blocks` / `items` / `elements` / `content_list` / `para_blocks` / `pages[*].blocks` | `_find_block_list` 递归查找 |
| block_type | `type` / `block_type` / `category` → `_norm_type` 归一 | image\|img\|figure\|fig\|picture→figure；equation\|formula\|latex\|math\|interline_equation\|inline_equation→formula；table→table；其余→text |
| content | `content` / `text` / `html` / `table_body` / `latex` / `markdown` / `caption` | dict/list 自动 `json.dumps` |
| page_num | `page_num` / `page_no` / `page`（原值）；`page_idx`（0-based，+1 归一） | 1-based |
| bbox | `bbox` / `box` / `poly` | 原样存 JSON |
| image_key（已上传场景） | `image_key` / `image_url` / `img_path` / `image_path` | MinerU 若已自传图则直接复用 |
| raw_image（待上传场景） | `image` / `image_base64` | 二进制或 base64，由 `_upload_figures` 解码上传 |

## 6. 已知契约收紧

- **SDK 模式强制要求 `pdf_bytes`**：云端 `MineruKIEClient` 需要 PDF 文件字节，而原 `parse_paper` 签名按 `pdf_key` 走。现 `pdf_bytes is None` 时记 warning 并抛 `ValueError`。未来 worker（任务1 的 upload/worker 接线，超出本次范围）负责从 MinIO 按 `pdf_key` 取字节后传入。`pdf_key` 参数暂保留（用于日志与未来本地 HTTP 模式）。
- **保留 `MINERU_BASE_URL`**：未删除，供未来本地容器 HTTP 模式备用；本次实际走 `MINERU_KIE_BASE_URL` 云端 SDK。
- **GROBID 路径**：`_extract_refs_grobid` / `_parse_tei_references` 原样保留未改动。
