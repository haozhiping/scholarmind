## 六、2026-06-05 修复记录：DB 驱动统一

**问题**：`parse_paper` 原签名 `db: AsyncSession`（SQLAlchemy），但调用方 `worker/main.py` 使用 `common.db.mysql_client.mysql`（`AsyncMySQLClient`），两套驱动不兼容导致调用崩溃。`indexer.py` 同样存在此问题。

**修复**：
- 移除 `services/parsing/parser.py` 中所有 `sqlalchemy` 依赖
- 移除 `services/indexing/indexer.py` 中所有 `sqlalchemy` 依赖
- `parse_paper` / `index_paper` 参数改为 `db=None`（默认 fallback 到全局 `mysql` 单例）
- 全部改用 `db.execute(sql, *args)` / `db.fetchall(sql, *args)`（`%s` 占位符 + autocommit，无需 `db.commit()`）
- `worker/main.py` 修复 `index_paper()` 调用签名（之前传参顺序错误：`index_paper(parse_result, user_id, paper_id)` → 修正为 `index_paper(user_id, paper_id, db=mysql)`）
- `Chunker.chunk_paper()` 适配 `fetchall()` 返回 `List[Dict]`（不再用元祖解包）

**影响文件**：`parser.py` | `indexer.py` | `worker/main.py`

## 七、2026-06-05 修复记录：接入 MinerU Agent 轻量解析 API

**问题**：KIE SDK 需要 `MINERU_PIPELINE_ID`（付费云 Pipeline），当前环境无法运行，Worker 解析阶段直接 `failed`。

**方案**：新增 `MINERU_PROVIDER=agent` 模式，对接 MinerU 官方 Agent 解析 API（签名上传 + 轮询），零额外依赖。

**修复文件**：

| 文件 | 改动 |
|---|---|
| `common/config.py` | 新增 `MINERU_PROVIDER`（agent/kie）、`MINERU_AGENT_BASE_URL`、`MINERU_LANGUAGE` 等配置 |
| `services/parsing/parser.py` | 新增 `_call_mineru_agent()`（签名上传→PUT 文件→轮询→下载 markdown）；新增 `_markdown_to_blocks()`（解析 markdown 为 text/table/figure/formula 四类 Block）；`_call_mineru()` 改为按 `MINERU_PROVIDER` 分发；`_mineru_to_blocks()` 兼容两种格式 |
| `.env.example` | 同步新增 Agent API 配置项 |

**Agent API 流水线**：

```
Worker 从 MinIO 下载 PDF
  ↓
POST /api/v1/agent/parse/file → task_id + signed file_url
  ↓
PUT pdf_bytes → file_url (直传 OSS)
  ↓
轮询 GET /api/v1/agent/parse/{task_id}
  ↓ state=done
下载 markdown_url → 解析为 blocks → 继续入库/索引
```

**Agent vs KIE 差异**：

| 维度 | Agent API | KIE SDK |
|---|---|---|
| 鉴权 | `Authorization: Bearer <MINERU_API_KEY>` | `MINERU_PIPELINE_ID` |
| 输出 | Markdown 文本 | 结构化 JSON (含 bbox/page_num) |
| 精度 | 无 bbox/page_num | 有 bbox/page_num |
| 图片 | Markdown 中为 CDN URL | base64 嵌入 |
| 依赖 | 无（纯 HTTP） | `mineru-kie-sdk` 包 |
